## 1. 目标与边界

验证任务 43、44、45 及 R05 重构在真实宿主中的表现：组合期间失焦、输入法停用及重新激活、输入目标切换或销毁后，旧编辑任务不能污染新输入，组合下划线及候选窗口不能残留或重新出现。另按两种切英文配置检查模式切换；这不等于失焦/停用清理策略改变。

本测试以真实界面观察和 ETW 日志为依据，不以 Mock 测试代替。设计依据见[组合生命周期说明](composition.md)，待办见[任务清单](arch.md)。

**重要判定规则：**

- 目前清理策略是保留预编辑文字、清除组合显示属性并结束旧组合，不要求失焦或停用时把文字删除。例如旧输入框留下普通文本 `ab`，不一定是缺陷。
- 宿主可能主动提交或取消组合。记录最终文字和宿主行为，不把“文字没有消失”直接判为失败。
- 重点检查：旧文字是否仍作为活动组合被后续按键修改、下划线是否持续残留、旧内容是否进入另一个输入框、旧 UI 是否重新出现。
- 单纯弹出菜单或切换窗口不保证触发 TSF 上下文移除。实际输入到另一个目标与仅覆盖主上下文要分别测试。
- 任务 47 不承担密码框识别、所有只读控件及游戏兼容性验收；这些属于任务 36。

## 2. 测试前准备

1. 保存现有工作，使用临时空白编辑器和下方本地测试页面，不使用真实业务内容。
2. 确认被测程序加载的是待验证 DLL。更新已安装 DLL 后完全退出并重新打开宿主；浏览器可能有后台进程，确认旧测试进程已正常退出。不要批量强制终止其他程序。
3. 准备一种其他输入法，例如微软拼音，供 `Win+Space` 切换。
4. 奇奇五笔设为中文、半角；关闭动态词频学习及按键音，记录原配置并在结束后恢复。打开候选窗口；若启用了独立状态栏，记录这一设置。
5. 启动日志监控器并开始采集，级别选择“全部 / All”或“详细 / Verbose”。默认 Info 不妨碍活跃 ETW 会话接收 Verbose，但 `LogLevel=Off` 会关闭日志，详见[日志指南](log.md)。
6. 确认采集能看到宿主的 `ActivateEx(version=..., arch=..., host=...)`。记录版本、架构及实际 PID/TID；浏览器承载输入法的进程可能不是主窗口进程。
7. 每个用例记录开始、结束的时间；导出完整区间，不要只保留成功或失败关键字。记录本地淘汰、ETW 丢失、解码和内存异常计数。

**组合准备动作：**聚焦目标，按 `a`、`b`，不按空格或数字选词。确认出现 `ab` 预编辑及候选窗口。若设置或宿主导致这组键自动提交，改用能稳定保持未提交组合的 2～3 个字母，并记录所用测试串。

**观察时点：**操作后立即观察，2 秒后再次观察，10 秒后检查是否有旧 UI 或文字重新出现。这些是人工观察窗口，不是 TSF API 的完成时限；不能仅凭超过 2 秒断定异步清理失败。

## 4. 用例

正常用例在 VS Code 和所选浏览器中各重复 **10 次**；宿主专属用例只在对应宿主执行。每次从无活动组合的状态开始。

### H01：基线输入、提交和取消

1. 在 A 建立组合。
2. 按空格提交首候选，检查只提交一次、候选窗口消失。
3. 再建立组合，按 Escape 取消。
4. 再次输入并提交，确认新输入正常。

通过：提交/取消后无组合下划线、旧候选窗不重现，没有重复文字。记录宿主显示预编辑的方式，作为后续对照。

### H02：组合期间切换到其他应用

1. 在 A 建立组合，`Alt+Tab` 切到一个临时记事本窗口。
2. 不输入任何内容，按上述观察时点检查旧候选窗口是否仍覆盖其他应用。
3. 切回 A，观察旧文本状态；若宿主恢复了组合，记录是否有对应的新激活或组合行为。
4. 结束当前组合，再输入新测试串并提交。

通过：失焦后旧候选不悬浮在其他应用上；恢复输入不重复提交、不卡住。若宿主只是保留主上下文，不能仅凭切回后重新显示候选断定旧回调复活。

### H03：同一宿主 A → B，第一键是 Backspace

1. B 预置普通文本 `BBBB`；VS Code 中将 B 光标放在末尾。
2. 在 A 建立未提交组合。
3. 鼠标点击 B 的文本末尾，立即按一次 Backspace。
4. 检查 B，再在 B 输入新组合并提交。

通过：B 的普通文本变为 `BBB`；不出现 A 的编码或候选，不因旧引擎仍在组合态而吞掉 B 的 Backspace。A 的宿主提交/保留/取消行为单独记录。

### H04：快速 A → B → A

1. 在 A 建立组合，切到 B，在 B 建立另一组不同的未提交组合。
2. 立即切回 A，先结束当前可见组合，再输入第三组测试串并提交。
3. 等待 10 秒，检查两个目标的内容、下划线和候选。

通过：新输入只影响当前目标；没有旧提交、旧取消或旧属性清理覆盖新组合，没有跨输入框文字或重复提交。

### H05：组合期间停用奇奇五笔

1. 在 A 建立组合，用 `Win+Space` 切到其他输入法。
2. 确认任务栏当前输入法已改变，观察旧候选和启用的奇奇独立状态栏。
3. 在 A 用新输入法输入一个明确不同的普通测试字符。
4. 保存这一轮日志。

通过：实际停用后奇奇候选及独立状态栏不再显示，也不被旧任务重建；旧奇奇组合不再参与新输入。

日志必须确认出现 `Deactivate` 或 `deactivate-begin`。若只有焦点变化而没有停用记录，此轮不能作为“停用”分支的覆盖证据。

### H06：停用后在同一目标重新激活

1. 重复 H05 的停用动作，随后用 `Win+Space` 切回奇奇。
2. 保持在同一个 A 中，立即输入不同的新组合。
3. 检查新下划线及候选是否稳定，再按空格提交。
4. 等待 10 秒，确认无旧 UI 或内容恢复。

通过：新周期输入正常，旧清理不清掉新组合的属性，旧任务不重新提交文字。日志应能关联实际停用与后续激活；`activation` 只在同一服务、同一线程中比较。

### H07：组合期间离开编辑区域及返回

1. 在 VS Code A 建立组合，鼠标打开菜单或点击非编辑区域，再返回 A。
2. 在浏览器 A 建立组合，点击页面按钮或非编辑区域，再返回 A。
3. 若宿主仍保留活动组合，先正常提交或取消，再验证新输入。

通过：无漂浮的旧候选、无崩溃或输入锁死，返回后输入正常。

本用例不要求一定取消主组合，也不要求一定出现 `OnPushContext` / `OnPopContext`；普通菜单或候选显示不能作为 TSF 模态入栈的证明。

### H08：销毁当前输入目标

1. 浏览器 A 建立组合，点击 `Remove A`，随后聚焦 B 输入并提交。
2. 刷新恢复 A，重新建立组合，再点击 `Reload`；刷新后在新的 A 输入并提交。
3. 另开一个临时测试标签页，建立组合后关闭该页，在另一个测试标签页输入。
4. VS Code 中，在空白临时编辑器建立组合后关闭该编辑器；如出现保存提示，正常处理，不强行退出真实工作文档。

通过：已移除目标的旧 UI 不残留；新页面/新编辑器不接收旧内容；无崩溃或持续输入异常。

页面导航可能让渲染进程退出或换 PID，需重新确认日志来源。旧进程退出后缺少析构日志，不单独作为泄漏证据。

### H09：候选位置变化后立即失焦或停用

1. 建立组合，移动宿主窗口或滚动页面，使候选需要重新定位。
2. 立即切到另一个应用，或切换输入法。
3. 切回/重新激活，在新的光标位置输入。
4. 条件允许时，跨不同 DPI 显示器重复。

通过：旧布局请求不能把候选重新显示在旧位置；新候选跟随当前目标。未发生布局通知时，记录为本分支未覆盖，不能强行判为通过。

编辑器内容滚动与整个宿主窗口移动应分别记录。若滚动时宿主返回的文本坐标不变，且相同操作下系统输入法也不移动候选，不单凭候选不跟随滚动判定奇奇失败；仍需检查失焦、停用和新组合阶段是否有旧 UI 残留或重新出现。

### H10：快速切换压力测试

在测试文档中连续执行 **20 轮**：建立组合 → A/B 切换 → 切换其他输入法 → 切回奇奇 → 输入并提交。

通过：无崩溃、卡死、跨目标写入、重复提交或累积的残留窗口；最后停止操作 10 秒仍稳定。记录失败发生的轮次，不以“最后能输入”掩盖中间失败。

## 5. 日志判读

按 **PID + TID + service** 关联服务；清理任务还要匹配 `cleanup`。不同进程或服务的相同编号不能混为一轮。

| 记录 | 判读 |
|---|---|
| `context-reset` | 旧目标周期失效；查看是否有旧 context/composition，以及是否尝试宿主清理 |
| `deactivate-begin`、`deactivate-local-complete` | 本地停用阶段；返回或本地完成不等于异步宿主清理完成 |
| `ui-end`、`ui-windows-destroyed` | UI 注册结束或窗口销毁结果；仍需实际观察是否残留 |
| `TsfCleanup ... sync-result` | 分别检查 `request_hr` 和 `session_hr`，不能只看外层成功 |
| `async-result ... queued=true` | 已排队，不代表已执行或成功 |
| `attribute-clear`、`end-composition` | 检查实际 HRESULT；两步任一失败都要单独记录 |
| `host-terminated`、`host-terminated-current` | 宿主已终止相关组合；不要求再出现主动 `end-composition` |
| `stale-edit-skipped`、`replaced-composition-edit-skipped` | 旧任务被拒绝是预期保护，不是失败 |
| `write-forced-async`、`write-requeued-behind-cleanup` | 新写入等待旧清理；结合后续实际输入结果判断 |
| `context-removed`、`skip-removed-context` | 已移除目标不得继续编辑；不要求为它新申请清理写权限 |
| `callback-exit`、`released`、`tracked_cleanups` | 不单独证明清理 API 成功、请求全部完成或完全无泄漏 |

不同宿主可以走同步清理、异步补救、宿主主动终止或上下文移除路径，不要求所有用例出现同一套日志。

`TF_E_SYNCHRONOUS` 后进入受控异步路径不直接算失败。其他非预期失败应保留完整 HRESULT、阶段、宿主条件和可见结果，不将其当成成功。

若捕获不到某分支，标“未覆盖”；若期间丢日志，修复采集条件后重测，不能仅凭事件缺失推断成功、泄漏或 Windows 丢回调。

### 判定与处理

[`ITfUIElementMgr::BeginUIElement` 的官方约定](https://learn.microsoft.com/en-us/windows/win32/api/msctf/nf-msctf-itfuielementmgr-beginuielement)

元素的自绘窗口。奇奇当前遵从此约定。

本次不可见的直接原因是 Copilot 对应的 TSF 宿主链要求隐藏输入法自绘候选窗，
不是日志所见的 `GetTextExt` 失败或候选窗口移到了屏幕外。结合正文正常及微软输入法
同样不可见的用户反馈，优先归为 Word Copilot 的宿主 UI 集成兼容性问题。
现有证据不能定位具体 Office 组件、UI sink 或嵌入控件，也不能证明宿主为何未绘制替代 UI。

本次只记录调查结果，不修改 FSM、候选定位或显示策略，不用强制弹窗绕过 FALSE，
避免破坏正常 UILess 宿主或产生重复候选 UI；不标记为已修复。
后续用空白文档和临时测试文字，在记录 Word/Office 版本及实际 IME 激活版本后，
分别复测正文与 Copilot，必要时向 Office 反馈脱敏截图和最短操作步骤。
